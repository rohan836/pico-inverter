## Open limitations (by design)

1. Exact 50 % per channel plus any dead time is impossible at a push-pull stage.
   The default build is symmetric with 200 us dead time and saturates just below
   50 % per channel (`LIM` above ~49 %). The exact complementary 50.000 %
   zero-dead-time image is `build-exact50/pico_inverter.uf2` — never power the
   MOSFET stage with it.
2. Hardware PWM build (`build-exact50`) cannot reach 1-7 Hz with a 16-bit counter;
   requests below 7.5 Hz clamp to ~7.45 Hz and report `LIM`. Its DUTY is locked.
3. The USB boot banner cannot be captured once the host opens the port after boot;
   connect a terminal before plugging in to see it, or watch the OLED instead.
4. There is still no current-sense or over-temperature shutdown in firmware.
5. The default build prints the boot banner once at boot; the line is lost if the
   host has no port open yet. A diagnostic `-DFW_BANNER_LOOP=1` reprints it every
   second for host capture. USB CDC output may appear as `\r\n`; terminals that
   expect `CRLF` only must be configured accordingly.
6. The USB boot banner prints `stored=1 f=60Hz` — the stored config is accepted by
   the current firmware, i.e. the user's re-learn of all seven remote buttons
   (including RESET ALL) persisted.
